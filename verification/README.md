# Conversion verification suite

Reusable scripts that exercise and verify the core `seqtool.py` conversion
paths against a song's chart data under `test_data/input/` (selected by music
id). Created while validating the Python 3.14 refactor and the SQ3 roundtrip
fixes; kept for regression checking after future changes to the SQ3/DTX/JSON
plugins.

## Run it

From the repository root (or anywhere — paths are resolved relative to the repo).
The `music_id` argument is required and selects which song under
`test_data/input/` to verify:

```sh
python verification/run_all.py <music_id>
```

It maps the id to the toolkit's file naming conventions:

```
test_data/input/m<id>_seq_ifs/   -> d<id>.sq3, g<id>.sq3, spu<id>*.va3, event<id>.*
test_data/input/m<id>_bgm_ifs/   -> bgm<id>*.bin, i<id>*.bin
```

If the expected inputs for the given id aren't present, the script prints the
missing paths and exits `1` without running anything. Output folders are
namespaced by id (`d<id>_json`, `g<id>_dtx_sounds`, ...), so different songs
don't collide.

Exit code is `0` when every required check passes, `1` otherwise — so it can be
wired into a pre-push hook or CI step.

## What it checks

| # | Path | Expected result |
|---|------|-----------------|
| 1 | drum `SQ3 -> JSON` | output.json produced |
| 2 | drum `JSON -> SQ3` | **byte-identical** to the original `.sq3` |
| 3 | guitar `SQ3 -> JSON` | output.json produced |
| 4 | guitar `JSON -> SQ3` | **100% semantic fidelity** (all 9 charts reparse identically) |
| 5 | drum `SQ3 -> DTX` | 4 difficulty `.dtx` files + `set.def` |
| 6 | guitar `IFS -> DTX` (with sounds) | 8 `.dtx` files (guitar+bass) + `set.def` |

### Why guitar is not byte-identical (and that's OK)

The drum chart round-trips byte-for-byte. The guitar/bass chart does not, for
two reasons that are *normalised away* by the JSON intermediate and do not
affect gameplay:

- **Chart ordering** — the reader groups charts (all guitar, then all bass);
  the original interleaves them on disk.
- **Auto-note lane byte (0x30)** — the original stores the underlying note id
  beneath the `auto_note` flag; the JSON collapses it to `note="auto"`, so the
  regenerated byte is `0xff` instead of the original id. Both read back as
  `"auto"`.

The suite confirms these are the *only* differences by re-parsing the output
and asserting full semantic equality, so the "byte-diff is benign" check passes
on semantic fidelity. If a future change breaks actual chart content, that
semantic check will fail.

## Files

- `run_all.py` — orchestrator; runs the six paths and prints a PASS/FAIL summary.
- `sq3_compare.py` — stdlib-only comparison helpers:
  - `binary_compare` — raw byte diff of two files
  - `load_charts_json` / `semantic_compare` — field-by-field chart JSON diff
  - `parse_sq3_events` — split an `.sq3` container into per-chart `0x40` event blocks
  - `event_multiset_compare` — match charts by identity, compare content ignoring order

`sq3_compare.py` is importable on its own for ad-hoc investigation, e.g.:

```python
import sys; sys.path.insert(0, "verification")
import sq3_compare as cmp
print(cmp.binary_compare("a.sq3", "b.sq3"))
ok, per = cmp.event_multiset_compare("a.sq3", "b.sq3")
```

## Requirements / notes

- Path 6 needs the full toolkit environment (`requirements.txt`): it extracts
  VA3 keysounds and renders via `pydub`/ffmpeg (the bundled `imageio-ffmpeg`
  binary is copied to `./ffmpeg.exe` automatically on first audio import).
- Outputs are written under `test_data/output/` (gitignored) and overwritten
  on each run.
- `--no-sounds` is used for the JSON roundtrips and the drum DTX path. It is
  **not** supported for guitar/bass DTX output (the renderer needs sound
  metadata to clip note durations), which is why path 6 runs the full IFS
  workflow with sounds.
